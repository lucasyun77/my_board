# ysb 계획 — 작게 쪼개고, 하나씩 확인하며 만든다

> 출처: 애디 오스마니의 공개 스킬 묶음 중 「계획과 작업 쪼개기」를 회장 현황판용으로 줄이고 한국어로 다시 쓴 것. 원본 허가문은 같은 폴더의 `원본-허가문.txt`.

## 핵심
일을 **한 번에 만들고 확인할 수 있는 크기**로 쪼개고, 작업마다 완료 조건과 확인 방법을 붙인다. 쪼개기를 잘해야 결과가 엉키지 않는다.

## 반드시 지킬 것 (저장소 지침 우선)
- 계획서와 회장님께 드리는 보고는 **모두 한국어**로 쓴다.
- 계획을 세우는 동안에는 **코드를 쓰지 않는다.** 읽기만 한다.
- 원하신 방식대로 안 되는 작업이 나오면 계획서 맨 앞에 **「⛔ 주의 — 의도대로 안 됨」**으로 먼저 알린다.
- `docs/MODULES.md`·`docs/UPGRADE_PLAN.md`의 공통 규칙을 따른다. 특히 메뉴 작업은 자기 메뉴 파일만 고치고, 공용 파일은 꼭 필요할 때만 최소로 고친다.

## 1단계: 읽기
- 승인된 기획서(`docs/기획/…`)와 관련 코드를 읽는다.
- 기존 메뉴의 방식(버튼·폼 등록 방법, 디자인 기준, 입력해서 찾는 선택칸 등)을 확인한다.
- 무엇이 무엇에 기대는지, 위험한 곳과 모르는 것을 적는다.

## 2단계: 세로로 자르기
데이터 전부, 그다음 화면 전부, 마지막에 연결하는 식으로 층별로 나누지 않는다. **회장님이 눌러서 확인할 수 있는 한 줄기**씩 끝까지 만든다.

나쁜 예: ① 샘플 데이터 전부 → ② 화면 전부 → ③ 버튼 연결
좋은 예: ① 지시를 등록하면 목록에 뜬다 → ② 목록에서 상태를 바꿀 수 있다 → ③ 기한 지난 지시가 위로 올라온다

작업 하나가 끝날 때마다 현황판이 **열리고 동작하는 상태**여야 한다.

## 3단계: 작업 쓰기
```markdown
## 작업 [번호]: [짧은 제목]
설명: 이 작업으로 무엇이 되는지 한두 문장.
완료 조건:
- [ ] 확인 가능한 조건 (세 개 이하)
확인 방법:
- [ ] 브라우저로 열어 화면 캡처로 확인 (휴대폰 폭·다크모드 포함)
- [ ] 다른 메뉴가 깨지지 않았는지 확인
먼저 끝나야 하는 작업: [번호 또는 없음]
고칠 파일: [예상 파일]
크기: 작음(1~2개 파일) / 보통(3~5개 파일)
```

**크기 기준**: 파일 다섯 개를 넘거나, 완료 조건을 세 줄로 못 쓰거나, 제목에 "그리고"가 들어가면 더 쪼갠다.

## 4단계: 순서와 점검 지점
1. 먼저 있어야 하는 것부터 만든다.
2. 위험한 작업(외부 연동, 공용 파일 수정)은 앞쪽에 둬서 일찍 부딪힌다.
3. 작업 2~3개마다 **점검 지점**을 둔다. 점검 지점에서는 전체 화면이 열리는지, 핵심 흐름이 처음부터 끝까지 되는지 확인한다.

## 저장
- 계획서는 `docs/기획/<기획서 이름>-계획.md`에 저장한다. 맨 위에 어느 기획서에서 나왔는지 적는다.
- **끝나지 않은 계획을 덮어쓰지 않는다.** 같은 이름의 계획에 완료되지 않은 작업이 남아 있으면, 같은 일을 고치는 경우에만 그 파일을 고친다. 다른 일이면 멈추고 회장님께 여쭌다. 다른 세션이 만드는 중일 수 있다.

## 계획서 양식
```markdown
# 만들기 계획: [이름]
나온 기획서: docs/기획/…

## 한눈에
무엇을 만드는지 한 문단.

## 주요 결정
- 결정과 이유

## 작업 목록
### 1부: 바탕
- [ ] 작업 1 …
- [ ] 작업 2 …
### 점검: 바탕 — 화면이 열리고 기존 메뉴가 그대로다
### 2부: 핵심 기능
- [ ] 작업 3 …
### 점검: 핵심 흐름이 처음부터 끝까지 된다
### 3부: 다듬기
- [ ] 작업 4 …
### 점검: 완료 조건을 모두 채웠고 미리보기 페이지를 드릴 준비가 됐다

## 위험과 대비
| 위험 | 영향(높음/보통/낮음) | 대비 |

## 남은 질문
```

## 승인과 진행
1. 계획서를 다섯 줄 안으로 요약하고 승인을 여쭌 뒤 **그 차례를 끝낸다.**
2. 승인되면 작업을 순서대로 만든다. 작업마다 확인이 통과하면 묻지 않고 자기 작업 갈래에 저장하고 원격에 올린다(저장소 지침). 본 갈래로 합치는 것은 회장님이 "합쳐"라고 하실 때만 한다.
3. 점검 지점은 스스로 확인하고 넘어간다. 막히거나 기획서와 달라져야 할 때만 멈추고 여쭌다.
4. 다 끝나면 미리보기 페이지를 띄우고, 완료 조건별로 됐는지 안 됐는지를 사실대로 보고한다.

## 흔한 핑계와 실제
| 핑계 | 실제 |
|---|---|
| "하면서 알아내겠다" | 그렇게 하면 엉키고 다시 하게 된다. 10분 계획이 몇 시간을 아낀다. |
| "작업이 뻔하다" | 그래도 적는다. 적어야 숨은 연결과 빠진 경우가 보인다. |
| "옛 계획서는 낡았으니 덮어쓰자" | 다른 세션이 만드는 중일 수 있다. 멈추고 여쭌다. |

## 시작 전 확인
- [ ] 모든 작업에 완료 조건과 확인 방법이 있다
- [ ] 순서가 앞뒤 관계에 맞다
- [ ] 다섯 개 파일을 넘는 작업이 없다
- [ ] 2~3개 작업마다 점검 지점이 있다
- [ ] 끝나지 않은 다른 계획을 덮어쓰지 않았다
- [ ] 회장님이 계획을 승인하셨다

# 잇다(ITDA) 기획서 — 서로 다른 컴퓨터의 AI 세션을 잇는 팀 협업 도구

> 작성 2026-11-14 · 대상: 회장님, 개발팀, 투자 검토자
> 용어: 회장님 말씀의 "섹션"은 AI 작업 창 하나(클로드 코드 같은 대화·터미널 한 개)를 뜻하며, 이 문서에서는 **세션**으로 적는다.

---

## 1. 한 줄 정의

**잇다**는 서로 다른 컴퓨터·서로 다른 계정에서 돌아가는 AI 세션들을 하나의 프로젝트로 묶고, **AI 본부장(진행도우미 에이전트)** 이 지식위키를 바탕으로 교통정리·코칭·검수를 맡아, 사람은 각자 전문 분야만 하고 합치는 일은 AI가 하게 만드는 **윈도우용 협업 앱**이다.

## 2. 왜 필요한가 (문제)

| 지금 벌어지는 일 | 결과 |
|---|---|
| AI가 생기면서 한 사람이 기획·개발·디자인을 다 하는 "1인 빌더"가 됐다 | 분업이 사라져 **생산성**이 오히려 떨어짐 |
| 개발자가 디자인까지 "할 수 있으니" 한다 | **품질**이 떨어짐 (전문가 분업이 더 낫다) |
| 동료 AI 세션끼리는 서로를 모른다 | 산출물을 사람이 복사·전달·합치기 → 시간 낭비, 충돌 |
| 팀마다 노하우가 따로 쌓인다 | 한 팀의 "운 좋은 발견"이 다른 팀에 전파되지 않음 |
| 세션이 멈춰 있어도 아무도 모른다 | 노는 세션 = 노는 생산 설비 |

## 3. 해결 (핵심 개념)

```
          ┌──────────── 프로젝트(메인 채팅) ────────────┐
          │  팀 메인 세션 (오케스트라 지휘: 클로드)      │
          │      ▲ 요청·산출물          ▲               │
          │  ┌───┴─────┐            ┌───┴─────┐         │
          │  │김디자이너│ 컴퓨터 A   │이개발자 │ 컴퓨터 B │
          │  │ 메인세션 │            │ 메인세션│         │
          │  │ ├ 하위1  │            │ ├ 하위1 │         │
          │  │ └ 하위2  │            │ └ 하위2 │         │
          │  └─────────┘            └─────────┘         │
          │        ▲ 감시·코칭·검수·일 시키기 ▲          │
          │        └──── AI 본부장 + 지식위키 ┘          │
          └─────────────────────────────────────────────┘
```

1. **세션 연결**: 각 컴퓨터의 잇다 앱이 중계 서버에 *밖으로 나가는 연결*만 맺는다(방화벽·공유기 설정 불필요). 클로드 코드의 "원격 제어"가 내 컴퓨터 세션을 다른 기기에서 조작하게 한 방식을 참고하되, 잇다는 **다른 사람·다른 계정의 세션끼리** 메시지·산출물을 주고받게 한다.
2. **위계형 합치기**: 디자이너는 자기 메인 세션에 "이 산출물을 팀 메인 세션에 보내서 합쳐 달라고 해"라고만 말한다. 팀 메인 세션이 여러 사람의 요청을 받아 순서·충돌을 정리(교통정리)한다. 사람은 합치기(머지) 고생에서 해방된다.
3. **AI 본부장**: 프로젝트 지식위키를 만들고, 메인 세션이 놓치거나 틀린 것을 코칭하고, 계획서 대비 빠진 일을 검수하고, 멈춘 세션에 일을 시키고, 당일 후속 계획을 세워 **노는 세션이 없게** 한다.
4. **본부장 복제(허브)**: 본부장이 자기 복제본을 다른 팀에 보내고, 두 위키의 **공통분모 위키**를 따로 관리한다. 팀이 10개·100개로 늘어도 하나의 오피스처럼 움직인다.

## 4. 사용자

| 사용자 | 하는 일 | 잇다에서 얻는 것 |
|---|---|---|
| 팀장·기획자 | 프로젝트(메인 채팅) 생성, 목표·지침 확정 | 팀 전체 진행 지도, 업무량, 후속 계획 |
| 개발자 | 개발 세션 여러 개 운영 | 남이 만든 산출물 자동 수신·합치기 |
| 디자이너 | 디자인 세션 운영 | 개발 몰라도 "보내 줘" 한마디로 반영 |
| 비개발 직원(마케팅·상품기획) | 컨셉·문안·이메일 산출물 | 같은 방식으로 업무 협업 (만능 업무 도구) |
| 경영진 | 여러 팀·브랜드 감독 | 팀 간 노하우 전파, 속도 맞추기 |

## 5. 화면 구성 (클로드 데스크톱 앱과 닮은 3단)

```
┌──────────┬──────────────────────┬────────────────────────────┐
│ ① 사이드  │ ② 세션 창             │ ③ 아티팩트 공간               │
│ 프로젝트A │ [터미널] [쉬운 채팅]   │ [연결 지도][대시보드][메신저] │
│ ├🖥 김디  │                      │ [지식위키][본부장]           │
│ │ ├ 세션1 │  > 명령 / 대화        │                            │
│ │ └ 세션2 │                      │   (선택한 메뉴 내용)          │
│ ├🖥 이개  │                      │                            │
│ │ └ 세션1 │                      │                            │
│ 프로젝트B │ [본부장 코칭 띠]       │                            │
└──────────┴──────────────────────┴────────────────────────────┘
```

### ① 왼쪽 사이드 메뉴
- 맨 위: **프로젝트(메인 채팅 세션)** 목록. 여러 개 가능. 하나 = 개발 프로젝트 또는 사업 프로젝트.
- 그 아래 나무 구조: 🖥 **컴퓨터 모양 + 사람 이름** → 그 사람이 연 **세션들**.
- 세션 옆 상태 점: 🟢 일하는 중 / 🟡 사람 대기 / 🔴 멈춤(본부장이 일 시킬 대상).

### ② 세션 창
- 기본은 **터미널 모드**(검은 화면, 명령·출력 그대로).
- 초보자용 **쉬운 채팅 모드**: 같은 내용을 말풍선으로 보여 준다(도구 실행은 접힌 카드).
- 아래에 **본부장 코칭 띠**: 도움 정도 설정(끔·가볍게·보통·적극)에 따라 제안이 뜬다.

### ③ 아티팩트 공간 (클로드처럼 여러 메뉴)
1. **연결 지도(마인드맵, 기본)** — 선택한 프로젝트 → 사람 → 세션 → 산출물. 산출물 누르면 바로 열림, 버전 번호(v1→v7)와 사람별 업무량 막대.
2. **협업 대시보드** — 목표·지침·계획 진척, 세션 가동률, 오늘 후속 계획. 직접 만들어 공유 가능.
3. **메신저** — 왼쪽 채널, 오른쪽 대화(슬랙처럼): 채널·개인 대화·멘션·스레드 답글·파일(산출물) 첨부·읽음 표시. 본부장도 채널 구성원이다.
4. **지식위키** — 본부장이 쌓는 프로젝트 지식(결정, 용어, 규칙, 브랜드 속성).
5. **본부장** — 검수표(계획서 항목별 완료 여부), 멈춘 세션 목록, 당일 후속 계획, 복제본(다른 팀) 현황.

## 6. AI 본부장 (진행도우미 에이전트) 상세

| 번호 | 역할 | 동작 방식 |
|---|---|---|
| 1 | 지식위키 구축 | 모든 세션의 대화 요약·산출물·결정사항을 위키 항목으로 정리 |
| 2 | 메인 세션 감독 | 메인 세션(클로드, 오케스트라 지침)이 놓친 요청·잘못된 합치기를 위키와 대조해 코칭 |
| 3 | 개인별 코칭 | 팀원이 정한 도움 정도(0~3단계)에 맞춰 제안 빈도·강도 조절. 진행 안내 틀(지스택·슈퍼파워즈 같은 방법론)을 위키와 함께 사용 |
| 4 | 계획서 검수 | 계획서 항목 ↔ 실제 산출물 대조. 다른 AI(지피티·재미나이 등)에게 교차 검수를 맡길 수 있음 |
| 5 | 멈춘 세션 깨우기 | 일정 시간 출력이 없으면 🔴 표시 → 후속 계획 중 다음 일을 보내 일 시킴(사람이 정한 범위 안에서) |
| 6 | 목표·지침·계획 관리 | 대시보드의 목표를 사람과 계속 다듬고, **당일 끊김 없는 후속 계획**을 세우는 것이 주목적 |
| 7 | 메신저로 의도 도출 | 세션이 아닌 **내장 메신저**에서 사람에게 묻고 답을 받아 방향을 확인 (차별점) |
| 8 | 복제·허브 | 복제본을 다른 팀에 보내 서로 소통, **공통분모 위키** 관리 → 서로 다른 서비스·팀이 하나의 오피스로 |
| 9 | 만능 업무 | 앱 개발뿐 아니라 화장품 제품·컨셉 개발 등 "산출물 만들기 + 이메일 보내기"로 끝나는 모든 업무 |

**안전 원칙**: 본부장이 세션에 일을 시키는 범위(읽기만 / 제안만 / 실행까지)는 프로젝트 주인이 정한다. 남의 컴퓨터에서 명령을 실행하려면 그 컴퓨터 주인의 허락 설정이 있어야 한다.

## 7. 차별점

1. **사람 단위가 아닌 "AI 세션 단위" 연결** — 메신저·협업툴은 사람을 잇지만, 잇다는 사람이 쓰는 AI 작업 창을 잇는다.
2. **위계형 자동 합치기** — 팀 메인 세션이 교통정리.
3. **메신저 속 본부장** — 의도 파악을 작업 창 밖, 대화 공간에서.
4. **본부장 복제로 팀 간 허브** — 대기업의 통합 오피스 역량을 소규모 회사에.
5. **노는 세션 0** — 멈춘 세션 감지와 당일 후속 계획.

## 8. 활용 시나리오 — 화장품 10개 브랜드 동시 출시

1. 본사 본부장이 브랜드 A 위키(브랜드 속성·금지 표현·원료 원칙)를 가진다.
2. 신규 라인 팀 B를 만들면 본부장 복제본이 B로 가서 A의 핵심 속성을 지키도록 코칭한다.
3. 나라별 팀(일본·미국·동남아)이 붙으면 공통분모 위키(브랜드 핵심)와 지역 위키(현지 규제·취향)를 나눠 관리.
4. 어느 팀이 "인플루언서 견본 발송 절차를 하루로 줄이는 법"을 찾으면 본부장이 전 팀에 전파.
5. 가장 빠른 팀의 계획표를 다른 팀이 따라 붙어 같은 속도로 진행 → 출시 속도 극대화.

## 9. 범위 — 시제품(이번) vs 정식 제품

| 기능 | 시제품 | 정식 |
|---|---|---|
| 3단 화면, 터미널·쉬운 채팅 전환 | ✅ | ✅ |
| 다른 컴퓨터 연결(중계 서버) | ✅ 실제 동작(웹소켓) | 암호화·인증·조직 관리 |
| 세션에서 실제 명령 실행 | ✅ 내 컴퓨터 명령/클로드 코드 호출 | 가상 터미널, 권한 격리 |
| 연결 지도·버전·업무량 | ✅ | ✅ |
| 메신저(채널·대화·멘션) | ✅ 기본 | 스레드·검색·알림 |
| 본부장 | 규칙 기반 + 클로드 연동 자리 | 클로드·지피티 교차 검수, 복제·허브 |
| 지식위키 | ✅ 기본 | 자동 요약, 공통분모 계산 |

## 10. 성공 지표

- 세션 가동률(일하는 시간 ÷ 열려 있는 시간) 60% → 85%
- 산출물 합치기 대기 시간 하루 → 1시간 이내
- 한 팀의 발견이 다른 팀에 적용되기까지 걸리는 시간 2주 → 1일
- 1인당 동시에 굴리는 세션 수 2개 → 5개

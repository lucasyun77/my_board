# 아이센스투게더 본제품 개발 계획서

> 작성 2026-11-21 · 작성 클로드 · 기준: 「01-기획서」, 「02-개발계획서」, 시제품 0.1.0
> 이 문서의 기간·인원은 모두 **예시 계획**입니다. 회장님 확정이 필요한 항목은 맨 끝 「결정 필요 사항」에 모았습니다.
> 회장님은 재미나이로 계획을 세우기를 원하셨습니다. 그런데 이 작업 환경에서는 재미나이를 부를 수 없어서, 회장님 선택에 따라 클로드가 작성했습니다.

---

## 1. 한 줄 목표

**아이센스그룹 전 직원이 매일 쓰는 협업 도구 1.0을 만든다.** 서로 다른 컴퓨터의 AI 세션이 안전하게 이어지고, AI 본부장이 진행을 챙기며, 회사 밖으로 나가는 것은 통제되는 도구다.
- 그다음 단계가 협력사 제공, 그다음이 외부 판매다.

## 2. 개발 원칙

| 원칙 | 뜻 |
|---|---|
| 우리가 첫 사용자 | 아이센스투게더를 아이센스투게더로 만든다. 개발 팀원 각자의 AI 세션을 이 앱으로 잇고, 본부장이 개발 진행을 관리한다 |
| 시제품을 버리지 않는다 | 러스트 중계 서버, 처리 규칙, 화면 구조는 살린다. 갈아엎지 않고 단단하게 만든다 |
| 보안이 먼저 | 계정·암호화·권한이 없는 기능은 사내에도 배포하지 않는다 |
| 사내 지침을 기능으로 | 급여 정보 보호, 외부 게시 사전 허락(전략실 승인번호)을 제품 안에 규칙으로 넣는다 |
| 한 번에 한 팀씩 | 한 팀에서 매일 쓰이는 것을 확인한 뒤 넓힌다 |

## 3. 시제품과 본제품의 차이

| 영역 | 시제품 0.1.0 (지금) | 본제품 1.0 (목표) |
|---|---|---|
| 로그인 | 이름만 입력, 모임 암호 | 회사 구글 계정 로그인, 기기 등록, 퇴사자 자동 차단 |
| 연결 | 사내망 웹소켓(암호화 없음) | 암호화 연결, 클라우드 중계 서버, 끊겨도 자동 재연결·밀린 내용 받기 |
| 저장 | 파일 하나 | 데이터베이스(포스트그레스), 산출물 파일 저장소, 매일 백업 |
| 세션 실행 | 한 번 실행하고 끝나는 명령 | 실제 터미널(대화형), 클로드 코드 세션을 그대로 붙이기, 여러 AI 도구 연결 |
| 합치기 | 요청·순서·기록 | 팀 메인 세션이 실제로 합친 결과를 버전으로 남기고, 되돌리기 |
| AI 본부장 | 규칙 + 클로드 연결 자리 | 클로드 기본, 다른 AI 교차 검수, 세션 대화 자동 요약 → 위키, 하루 두 번 후속 계획 배달 |
| 메신저 | 채널·개인 대화·답글 | 검색, 윈도우 알림, 파일, 읽음 표시, 본부장의 질문 카드 |
| 팀 간 허브 | 같은 서버 안 공통 위키 복제 | 다른 팀·다른 서버 사이 본부장 복제본 연결, 공통분모 위키 자동 계산 |
| 배포 | 서명 없는 실행 파일 | 회사 서명 설치 파일, 자동 업데이트 |
| 운영 | 없음 | 오류 보고, 사용 현황 화면, 감사 기록 |

## 4. 본제품 구조

```
 [직원 컴퓨터]                                  [회사 클라우드]
 아이센스투게더 앱 (러스트·타우리)                  중계 서버 무리 (러스트)
  ├ 화면 3단                     ── 암호화 연결 ──▶  ├ 로그인 확인 (회사 구글 계정)
  ├ 세션 실행기                                      ├ 실시간 전달 (프로젝트 방)
  │  · 실제 터미널                                   ├ 처리 규칙 (시제품 규칙 확장)
  │  · 클로드 코드 세션 연결                           ├ 데이터베이스 · 파일 저장소
  │  · 다른 AI 도구 연결                              ├ 감사 기록
  ├ 내 컴퓨터 권한 문지기                             └ AI 본부장 일꾼
  │  (남이 보낸 일은 내 허락 후 실행)                     · 클로드 (기본)
  └ 자동 업데이트                                         · 지피티·재미나이 (교차 검수)
                                                         · 위키 검색 (의미 검색)
```

- **밖으로만 연결**하는 방식은 그대로 둔다. 직원 컴퓨터에 들어오는 문은 열지 않는다.
- **내 컴퓨터 권한 문지기**: 다른 사람이나 본부장이 내 세션에 일을 보내면 화면에 카드가 뜨고, 내가 허락해야 실행된다. 사람마다 「읽기만 / 제안만 / 실행까지」를 고른다.
- **본부장 일꾼**은 서버에서 따로 돈다. AI 비용은 프로젝트별 한도를 두고 대시보드에 보인다.

## 5. 사내 지침을 제품 규칙으로

| 지침 | 제품에서 하는 일 |
|---|---|
| 급여·보수 정보 보호 | 위키·메신저·산출물에서 개인 보수 정보로 보이는 내용을 찾으면 본부장이 저장·요약·전파하지 않고 가린다. 급여 담당자 예외는 관리자 화면에서 지정한다 |
| 업무 산출물 외부 게시 사전 허락 | 산출물을 회사 밖으로 공유·내보내기할 때 전략실 승인번호를 입력해야 열린다. 번호가 없으면 막고 승인 절차를 안내한다 |
| 개인 계정으로 옮기기 금지 | 회사 계정이 아닌 곳으로 내보내기를 막는다 |
| 외부 배포 전 허락 안내 | 프로그램 산출물을 외부 배포 상태로 바꿀 때 한 번 안내한다 |

## 6. 단계별 계획 (예시 일정)

| 단계 | 기간(예시) | 만드는 것 | 넘어가는 기준 |
|---|---|---|---|
| 0. 기반 | 2026-12 (4주) | 회사 구글 계정 로그인, 암호화 연결, 데이터베이스 저장, 클라우드 중계 서버 1대, 서명 설치 파일·자동 업데이트, 오류 보고 | 개발팀 4명이 앱으로 로그인해 같은 프로젝트를 봄 |
| 1. 사내 알파 | 2027-01 ~ 02 (6주) | 실제 터미널, 클로드 코드 세션 연결, 권한 문지기, 합치기 결과 버전·되돌리기, 메신저 검색·알림 | 개발팀이 아이센스투게더 개발 자체를 이 앱으로 2주 연속 진행 |
| 2. 사내 베타 | 2027-03 ~ 04 (6주) | 본부장 1.0(클로드 기본 + 교차 검수 + 자동 위키 + 하루 두 번 후속 계획), 사내 지침 규칙, 관리자 화면, 감사 기록 | 화장품 브랜드 팀 1곳 + 개발팀이 매일 사용, 노는 세션 비율 측정 시작 |
| 3. 1.0 사내 정식 | 2027-05 (4주) | 성능·안정화, 사용 설명 영상, 사내 교육, 전 직원 배포 | 전 직원 설치, 주간 사용자 비율 목표 달성 |
| 4. 팀 간 허브 | 2027-06 ~ 07 (8주) | 다른 팀·다른 서버 사이 본부장 복제본, 공통분모 위키 자동 계산, 발견 전파 | 브랜드 팀 2곳이 공통 위키로 협업 |
| 5. 외부 판매 준비 | 2027 하반기 | 조직 가입·요금·회사별 데이터 분리, 맥 지원 | 협력사 3곳 시범 |

## 7. 개발 방식: AI 세션 팀으로 만든다

| 역할 | 사람 | 그 사람이 돌리는 AI 세션 (예시) |
|---|---|---|
| 총괄·기획 | 1명 | 팀 메인 세션(지휘), 요구사항 세션 |
| 러스트(서버·앱) | 1명 | 서버 세션, 앱 실행기 세션, 시험 세션 |
| 화면 | 1명 | 화면 세션, 디자인 반영 세션 |
| AI·본부장 | 1명 | 본부장 세션, 검수 세션 |
| 디자인 | 0.5명 | 시안 세션 |
| 품질·보안 | 0.5명 | 시험 자동화 세션, 보안 점검 세션 |

- 각자 AI 세션 2~4개를 굴리고, 팀 메인 세션이 합친다.
- 본부장은 이 계획서를 검수표로 삼아 매일 빠진 일과 멈춘 세션을 챙긴다.
- 매주 금요일 회장님께 진행 현황판(대시보드) 링크를 보고한다.

## 8. 품질과 운영

- **시험**: 처리 규칙 시험(지금 5개 → 1.0까지 200개 이상), 화면 자동 시험, 윈도우 실제 기기 시험(윈도우 10·11 각 1대 상시).
- **배포**: 회사 코드 서명 인증서로 서명, 자동 업데이트, 문제가 생기면 바로 이전 판으로 되돌림.
- **장애 대응**: 중계 서버 2대 이상, 3초 단위 저장, 매일 백업, 장애 시 사내 메신저 공지.
- **측정**: 세션 가동률, 합치기 대기 시간, 팀 간 전파 시간, 1인당 세션 수(기획서의 성공 지표).

## 9. 위험과 대응

| 위험 | 대응 |
|---|---|
| 남의 컴퓨터에서 명령 실행 → 보안 사고 | 권한 문지기, 기본값 「제안만」, 실행은 주인 허락 후, 모든 실행 감사 기록 |
| AI 비용 증가 | 프로젝트별 한도, 정해진 명령은 규칙으로 처리, 사용량 대시보드 |
| 직원이 안 씀 | 한 팀씩 확대, 쉬운 채팅 방식 기본, 본부장 도움 정도 조절 |
| AI 도구 회사들의 변경 | 연결부를 따로 만들어 클로드·지피티·재미나이를 갈아 끼울 수 있게 함 |
| 회사 정보 유출 | 외부 게시 승인번호, 개인 계정 내보내기 차단, 보수 정보 가림 |

## 9-1. 준비물이 필요한 시점

> **언제 필요한가 (2026-11-21 정리)**: 아래 준비물(구글 로그인 앱 번호, 상시 켜진 서버, 코드 서명 인증서)은 **개발에는 필요 없습니다.** 개발은 클로드 클라우드에서 계속합니다. 직원들이 실제로 쓰기 시작할 때 필요합니다.
> - 사내 시범: 서버는 팀장 컴퓨터(앱의 「중계 서버 켜기」 단추), 로그인은 모임 암호로 대신할 수 있습니다.
> - 전 직원 배포 전: 세 가지를 갖춥니다.

## 10. 결정 필요 사항 (회장님)

1. 영문 표기 확정: iSens Together / iSensTogether 중 무엇으로 할지
2. 중계 서버 위치: 회사 클라우드(어느 회사 클라우드) 또는 사내 서버
3. 개발 인원과 시작일(위 4.5명 예시)
4. 1.0 사내 정식 목표 시점(예시 2027-05)
5. 교차 검수에 재미나이를 쓸지. 쓴다면 정확한 모델 이름과 회사 열쇠 발급
6. 첫 시범 팀(예: 화장품 브랜드 팀 1곳)

## 11. 승인 후 첫 2주 할 일

1. 회사 구글 계정 로그인 연결 설계, 시범 계정 4개 준비
2. 클라우드 중계 서버 1대 준비, 암호화 연결 적용
3. 저장 방식을 파일 → 데이터베이스로 바꾸기(처리 규칙은 그대로)
4. 코드 서명 인증서 신청, 자동 업데이트 시험
5. 윈도우 실제 기기 시험 장비 2대 준비
6. 개발팀 4명이 시제품으로 이 계획서의 할 일을 계획 항목에 넣고 시작

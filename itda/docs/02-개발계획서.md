## 1. 구조 한눈에

```
 [김하늘 컴퓨터]            [이도윤 컴퓨터]            [최민준 컴퓨터 = 팀장]
 잇다 데스크톱 앱            잇다 데스크톱 앱            잇다 데스크톱 앱
  ├ 화면(3단)                ├ 화면                     ├ 화면
  ├ 명령 실행기               ├ 명령 실행기              ├ 명령 실행기
  │  (터미널 / 클로드 코드)   │                          └ ★ 중계 서버 + AI 본부장 (켜기 버튼 하나)
  └─ 밖으로 나가는 연결 ──────┴──── 웹소켓 ─────────────────┘
                                   │
                         (선택) 클로드 메시지 기능 ← 본부장 답 쓰기
```

- **밖으로 나가는 연결만** 쓴다: 각 앱이 중계 서버에 붙는다. 공유기 포트 열기 불필요(중계 서버를 사내망 한 대 또는 클라우드 한 대에 둠).
- 중계 서버는 **한 곳에서만 상태를 바꾼다**(처리 규칙 한 곳). 바뀐 상태를 모두에게 다시 뿌린다 → 모든 컴퓨터가 같은 지도를 본다.
- 세션 출력 한 줄 한 줄은 가볍게 따로 뿌린다(전체 상태를 매번 보내지 않음).

## 2. 기술 선택

| 영역 | 선택 | 이유 |
|---|---|---|
| 데스크톱 껍데기 | 러스트 + 타우리 2 | 윈도우 기본 웹보기(웹뷰2) 사용 → 설치 파일 작음(전자 방식 대비 수십 분의 1), 러스트로 명령 실행·서버 내장 |
| 화면 | 순수 자바스크립트·HTML·CSS(빌드 없음) | 시제품 속도. 같은 화면을 웹 보기·미리보기·데스크톱에서 그대로 씀 |
| 중계 서버 | 러스트(엑섬·토키오) 웹소켓 | 한 대가 수백 연결 처리, 실행 파일 하나로 배포 |
| 저장 | 시제품: 파일 하나(제이슨). 정식: 포스트그레스 | 시제품은 설치 없이 |
| AI 본부장 | 러스트 규칙 + 클로드 메시지 기능(열쇠 있을 때) | 열쇠 없이도 돌아가고, 있으면 더 똑똑해짐 |
| 세션 실행 | 터미널: 윈도우 명령창, 쉬운 채팅: `claude -p "말"` (설정에서 바꿈) | 클로드 코드·다른 AI 도구 무엇이든 붙임 |

## 3. 폴더 구성 (저장소 `itda` 폴더)

| 위치 | 내용 |
|---|---|
| `relay/src/state.rs` | 공유 상태 자료 구조와 처리 규칙(프로젝트·세션·산출물 버전·메신저·위키·계획·합치기 요청·대시보드) |
| `relay/src/agent.rs` | AI 본부장: 멈춘 세션 깨우기, 검수, 당일 후속 계획, 메신저 응답, 클로드 호출 + 시험 5개 |
| `relay/src/lib.rs` | 웹소켓 중계, 저장, 주기 점검 |
| `relay/src/main.rs` | 중계 서버 단독 실행 파일 |
| `app/src-tauri/` | 윈도우 앱: 명령 실행, 컴퓨터 정보, 중계 서버 켜기 |
| `app/ui/` | 3단 화면(사이드·세션·아티팩트 공간), 시연 자료 |
| `docs/` | 기획서·개발 계획서·제품설명서·브랜드기획서·쉬운 설명서·투자 자료 |
| `manual/` | 사용 설명 그림 |

## 4. 주고받는 약속(통신 규약)

앱 → 서버 (모두 `{"op": 이름, ...}`)

| 동작 | 하는 일 |
|---|---|
| `hello` | 첫 인사(내 이름·컴퓨터·모임 암호) |
| `createProject` / `joinProject` / `updateProject` | 프로젝트(메인 채팅) 만들기·합류·목표/지침 |
| `openSession` / `setSessionStatus` / `log` | 세션 열기·상태·출력 한 줄 |
| `publishArtifact` | 산출물 올리기(같은 이름이면 버전 +1) |
| `sendRequest` / `resolveRequest` | 다른 세션에 합치기 요청 / 팀 메인이 합침·반려 |
| `createChannel` / `post` | 메신저 채널·글(답글·산출물 첨부·@부르기) |
| `wiki` / `plan` / `board` | 지식위키·계획 항목·공유 대시보드 |
| `setHelpLevel` / `agentReview` | 본부장 도움 정도 / 지금 점검 |

서버 → 앱: `welcome`, `snapshot`(전체 상태), `log`(한 줄), `error`.

## 5. 단계별 계획 (예시 일정)

| 단계 | 기간(예시) | 만드는 것 | 끝났다는 기준 |
|---|---|---|---|
| 0. 시제품 | 2026-11 (완료) | 3단 화면, 중계 서버, 본부장 규칙, 윈도우 실행 파일 | 컴퓨터 두 대가 같은 프로젝트에서 요청·산출물·메신저를 주고받음 |
| 1. 사내 시범 | 4주 | 설치 파일, 모임 암호 → 계정 로그인, 연결 암호화(웹소켓 보안), 가상 터미널(대화형 명령), 클로드 코드 세션 그대로 붙이기 | 한 팀 5명이 1주 동안 매일 사용 |
| 2. 본부장 강화 | 4주 | 클로드 본부장 기본화, 지피티·재미나이 교차 검수, 세션 대화 자동 요약 → 위키, 하루 후속 계획 자동 배달(아침 9시·오후 2시) | 노는 세션 비율 30% → 10% |
| 3. 팀 간 허브 | 6주 | 본부장 복제본(다른 중계 서버와 연결), 공통분모 위키 자동 계산, 팀 간 발견 전파 | 두 팀(예: 화장품 브랜드 2개)이 공통 위키로 협업 |
| 4. 공개 | 8주 | 조직 관리, 권한(읽기·제안·실행), 요금, 맥 지원 | 협력사 3곳 사용 |

필요 인원(예시): 러스트 1, 화면 1, AI·본부장 1, 디자인 0.5, 기획 0.5.

| 연결 지도(사람·세션·산출물·버전·업무량), 산출물 열기 | ✅ |
| 공유 대시보드 만들기 | ✅ |
| 메신저(채널·개인 대화·답글·@부르기·첨부·안 읽음) | ✅ (검색·알림은 1단계) |
| 지식위키(팀·공통분모) | ✅ |
| 본부장: 멈춘 세션 감지·일 시키기, 검수표, 후속 계획, 메신저에서 의도 묻기 | ✅ 규칙. 클로드 열쇠를 넣으면 클로드가 답 |
| 본부장 복제본 | 🔶 같은 중계 서버 안의 다른 프로젝트로 공통 위키 복제까지. 서로 다른 서버(회사) 간은 3단계 |
| 다른 AI 교차 검수 | 🔶 자리만 있음(2단계) |

## 7. 실행 방법 (개발자용)

```
# 중계 서버 (시연 자료 포함)
cargo run -p itda-relay -- --demo --port 7878
# 브라우저로 http://서버주소:7878 → 바로 연결 방식으로 열림

# 윈도우 실행 파일 만들기 (윈도우 컴퓨터에서)
cargo install tauri-cli --version "^2"
cd app/src-tauri && cargo tauri build      # 설치 파일(엔에스아이에스) 생성

# 리눅스에서 윈도우용 실행 파일만 만들기(이번 시제품 방식)
rustup target add x86_64-pc-windows-gnu    # mingw-w64 필요
cargo build --release -p itda-desktop --target x86_64-pc-windows-gnu
```

클로드 본부장을 켜려면 중계 서버를 돌리는 컴퓨터에 환경 변수 `ANTHROPIC_API_KEY` 를 넣는다(저장소에 넣지 않는다). 모델은 `ITDA_MODEL` 로 바꿀 수 있다(기본 클로드 오퍼스 5.5).

## 8. 위험과 대응

| 위험 | 대응 |
|---|---|
| 남의 컴퓨터에서 명령 실행 → 보안 사고 | 시제품은 **자기 컴퓨터 명령만** 실행. 다른 사람 세션에는 "요청"만 보냄. 정식에서 권한 3단계(읽기·제안·실행) |
| 중계 서버 장애 | 상태를 3초마다 파일 저장, 재시작 시 복구. 정식은 데이터베이스 |
| 본부장이 너무 말이 많음 | 사람마다 도움 정도 0~3, 같은 경고 되풀이 막기 |
| AI 비용 | 정해진 명령(목표·할 일·점검)은 규칙으로, 자유 질문만 클로드 |

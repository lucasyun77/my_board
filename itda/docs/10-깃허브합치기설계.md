# 2번 「실제 합치기」 설계서 — 깃허브 방식

> 작성 2026-11-21 · 마더 세션 · 회장님 지시: "깃허브 방식으로 2번 진행"
> 원칙: **앱은 파일을 나르지 않는다.** 파일은 회사 깃허브 저장소에 있고, 앱은 「누가·어느 갈래를·언제 합칠지」를 지휘한다. 하위 세션들은 이 문서의 이름과 모양을 그대로 지킨다.

## 1. 흐름

```
[김하늘 세션]                         [팀 메인 세션]
 작업 폴더 = 저장소 복사본               작업 폴더 = 저장소 복사본(기본 갈래)
 갈래 together/김하늘/로그인시안
   │ ① 「팀 메인에 합치기 요청」
   │    앱이 대신: 저장(커밋) → 깃허브에 올림
   │ ② 요청에 갈래·기록 번호만 실어 보냄 ──▶ 요청 카드: 갈래·기록·부탁 말
   │                                       │ ③ 「합치기 맡기기」(사람 허락)
   │                                       │    앱이 팀 메인 클로드에게 합치기 지시
   │                                       │ ④ 클로드: 받기 → 합치기 → 충돌 정리 → 시험 → 올리기
   │ ⑥ 「합쳐졌습니다(기록 abc1234)」 ◀──── ⑤ 결과 줄을 읽어 요청을 「합침」으로
```

## 2. 중계 서버 자료 (마더 세션)

- 프로젝트: `repo`(저장소 주소, 예 `https://github.com/회사/앱.git`), `baseBranch`(기본 갈래, 기본값 `main`)
  - 동작 `updateProject { projectId, repo?, baseBranch? }`
- 합치기 요청 `requests[]` 에 칸 추가: `branch`, `commit`, `resultCommit`, `resultNote`
  - 동작 `sendRequest { fromSession, toSession, artifactId?, note, branch?, commit? }`
  - 동작 `resolveRequest { requestId, status, commit?, note? }`
  - status: `대기` → `합치는 중` → `합침` | `충돌` | `반려` | `되돌림`

## 3. 데스크톱 앱 깃 명령 (하위 세션 G)

모두 이 컴퓨터에 설치된 `git` 과, 사용자가 이미 해 둔 깃허브 로그인(윈도우 자격 증명 관리자)을 쓴다. 오류는 한국어 문장으로 돌려준다.

| 명령 | 인자 | 돌려줌 | 하는 일 |
|---|---|---|---|
| `git_check` | `{}` | `{ installed, version }` | git 설치 확인 |
| `git_prepare` | `{ sessionId, repo, baseBranch, branch, dir? }` | `{ dir, branch, created }` | 폴더에 저장소가 없으면 복제한다(`문서/iSensTogether/저장소/<저장소이름>-<sessionId>`). 기본 갈래를 최신으로 받고, 작업 갈래가 없으면 기본 갈래에서 만들어 옮긴다 |
| `git_status` | `{ dir }` | `{ branch, changed, ahead, behind, head }` | 바뀐 파일 수, 올리지 않은 기록 수 등 |
| `git_save_push` | `{ dir, message }` | `{ branch, commit, pushed, nothingToCommit }` | 바뀐 것을 모두 저장하고 원격에 올린다(`-u`). 바뀐 게 없으면 저장 없이 지금 기록을 올린다 |
| `git_head` | `{ dir }` | `{ branch, commit }` | 지금 갈래와 마지막 기록 |

- 작업 갈래 이름: `together/<사람이름>/<세션제목>`. 앱이 영문·숫자·한글·하이픈만 남겨 만든다.
- 팀 메인 세션은 기본 갈래 그대로 쓴다(작업 갈래 없음).

## 4. 팀 메인 클로드에게 주는 합치기 지시 (화면이 보냄)

```
[아이센스투게더 합치기 지시]
요청 번호: r12
보낸 사람: 김하늘 · 「로그인·예약 화면 시안」
합칠 갈래: together/김하늘/로그인시안 (기록 abc1234)
부탁: 예약 버튼 색을 바꿨어요. 앱에 반영해 주세요.

할 일:
1. git fetch origin 후 기본 갈래(main)를 최신으로 맞춘다.
2. origin/together/김하늘/로그인시안 을 --no-ff 로 합친다.
3. 충돌이 나면 양쪽 뜻을 살려 정리한다. 판단이 어려우면 고치지 말고 멈춘다.
4. 시험이나 빌드 명령이 있으면 돌린다.
5. 성공하면 main 을 원격에 올린다.
6. 마지막 줄에 정확히 이렇게 쓴다:
   합치기 결과: 성공 <합친 기록 7자리>
   또는
   합치기 결과: 실패 <이유 한 줄>
```

화면은 팀 메인 세션의 `result` 사건 직전 `text` 들에서 `합치기 결과:` 줄을 찾는다.
- 성공이면 `resolveRequest(합침, commit)` 을 보낸다.
- 실패면 `resolveRequest(충돌, note)` 를 보낸다.
- 줄이 없으면 `git_head` 로 확인하고, 그래도 모르면 「결과를 확인해 주세요」 카드를 띄운다.

## 5. 되돌리기

합침 상태 요청 카드에 「되돌리기」 단추를 둔다. 누르면 팀 메인 클로드에게 지시한다: `git revert -m 1 <resultCommit>` 후 올리고, 마지막 줄 `되돌리기 결과: 성공 <기록>`. 성공하면 `resolveRequest(되돌림, commit)`.

## 6. 개발자가 아닌 직원

- 깃허브를 몰라도 된다. 저장·올리기·갈래는 앱이 뒤에서 한다. 화면에는 「저장소 연결됨 · 바뀐 파일 3개」 정도만 보인다.
- 필요한 것: 회사 깃허브 계정과 저장소 쓰기 권한, 컴퓨터에 깃(윈도우용 깃 설치 시 로그인 관리자 포함). 직원이 실제로 쓰기 시작할 때 준비한다.
- 큰 디자인 파일은 나중에 대용량 파일 기능이나 구글 드라이브 연결로 보완한다.

# 잇다 제품설명서

> 작성 2026-11-14 · 대상: 도입을 검토하는 팀장·경영진·협력사
> 기준 문서: 「01-기획서」
> 이 문서의 모든 가격·수치는 **예시**이며 확정된 값이 아니다.

---

## 1. 한 줄 소개

**잇다는 서로 다른 컴퓨터, 서로 다른 계정에서 돌아가는 AI 작업 창(세션)을 하나의 팀으로 이어 주고, AI 본부장이 교통정리·코칭·검수를 맡아 사람은 자기 전문 분야에만 집중하게 하는 윈도우용 협업 앱입니다.**

```
   지금                                   잇다를 쓰면
 ┌──────┐ ┌──────┐ ┌──────┐            ┌──────┐ ┌──────┐ ┌──────┐
 │디자인 │ │ 개발 │ │마케팅 │            │디자인 │ │ 개발 │ │마케팅 │
 │ 세션 │ │ 세션 │ │ 세션 │            │ 세션 │ │ 세션 │ │ 세션 │
 └──────┘ └──────┘ └──────┘            └──┬───┘ └──┬───┘ └──┬───┘
   서로 모름. 사람이 복사·전달·합치기          └────┬───┴────┬───┘
                                            팀 메인 세션 (합치기)
                                                 │
                                         AI 본부장 + 지식위키
```

## 2. 누구를 위한 것인가

| 대상 | 지금의 불편 | 잇다로 달라지는 점 |
|---|---|---|
| 이미 AI로 일하는 직원 | 내 AI 결과물을 동료에게 옮기려면 복사·붙여넣기·파일 전달 | "팀 메인 세션에 보내 줘" 한마디로 전달·합치기 |
| 팀장·기획자 | 누가 무엇을 하고 있는지, 무엇이 빠졌는지 알기 어렵다 | 연결 지도와 대시보드로 한눈에 확인 |
| 디자이너·마케터·상품기획자 | 개발 지식 없이 결과물을 제품에 반영하기 어렵다 | 쉬운 채팅 화면에서 말로 요청 |
| 경영진 | 여러 팀·브랜드의 노하우가 따로 논다 | 본부장 복제본이 팀 사이 공통 지식을 관리·전파 |
| 소규모 회사 | 대기업처럼 모든 도구를 하나로 묶을 여력이 없다 | 하나의 앱으로 세션·메신저·위키·검수를 묶음 |

**한마디로**: 한 사람이 다 하는 "1인 빌더" 대신, 각자 잘하는 일을 하고 AI가 이어 붙이는 **분업형 팀**을 원하는 조직을 위한 도구다. 앱 개발뿐 아니라 화장품 제품·컨셉 개발처럼 "산출물을 만들고 전달하는" 모든 업무에 쓴다.

## 3. 핵심 기능 8가지

| 번호 | 기능 | 한 줄 설명 |
|---|---|---|
| 1 | 3단 화면 | 왼쪽 목록 · 가운데 세션 창 · 오른쪽 작업 공간 |
| 2 | 세션 연결 | 다른 컴퓨터·다른 계정의 세션끼리 메시지·산출물 주고받기 |
| 3 | 위계형 합치기 | 팀 메인 세션이 여러 사람의 결과물을 순서대로 정리해 합침 |
| 4 | 연결 지도 | 프로젝트 → 사람 → 세션 → 산출물을 나무 모양 지도로 |
| 5 | 협업 대시보드 | 목표·계획 진척, 세션 가동률, 오늘의 후속 계획 |
| 6 | 메신저 | 채널·개인 대화·멘션·답글, 본부장도 대화 상대 |
| 7 | 지식위키 | 결정·용어·규칙·브랜드 속성을 자동으로 쌓는 프로젝트 사전 |
| 8 | AI 본부장 | 코칭·검수·멈춘 세션 깨우기·후속 계획·팀 간 허브 |

### 3-1. 3단 화면

```
┌──────────┬──────────────────────┬────────────────────────────┐
│ ① 목록    │ ② 세션 창             │ ③ 작업 공간                  │
│ 프로젝트가 │ [터미널] [쉬운 채팅]   │ [연결 지도][대시보드][메신저] │
│ ├ 김디자인│                      │ [지식위키][본부장]           │
│ │ ├ 세션1 │   명령 또는 대화      │                            │
│ │ └ 세션2 │                      │   선택한 메뉴 내용            │
│ ├ 이개발  │                      │                            │
│ │ └ 세션1 │                      │                            │
│ 프로젝트나 │ [본부장 코칭 띠]       │                            │
└──────────┴──────────────────────┴────────────────────────────┘
```

- **① 목록**: 맨 위에 프로젝트(팀 메인 채팅) 목록, 그 아래 "컴퓨터 + 사람 이름" 아래로 그 사람이 연 세션들이 나무 모양으로 달린다.
- 세션 옆 상태 점: 🟢 일하는 중 · 🟡 사람 대답 기다림 · 🔴 멈춤(본부장이 챙길 대상)
- **② 세션 창**: 기본은 검은 화면의 터미널 방식. 초보자는 **쉬운 채팅 방식**으로 바꿔 말풍선으로 본다.
- 아래쪽 **본부장 코칭 띠**: 도움 정도(끔·가볍게·보통·적극)에 맞춰 제안이 뜬다.

### 3-2. 세션 연결

- 각 컴퓨터의 잇다 앱이 **중계 서버로만** 연결한다. 동료 컴퓨터에 직접 접속하지 않는다.
- 다른 사람·다른 계정의 세션이어도 같은 프로젝트에 초대되면 서로 메시지와 산출물을 주고받는다.
- 클로드 코드의 원격 제어 방식(내 세션을 다른 기기에서 조작)을 참고했지만, 잇다는 **남의 세션과 내 세션을 잇는** 데 초점이 있다.

### 3-3. 위계형 합치기

```
 디자이너: "이 시안을 팀 메인 세션에 보내서 합쳐 달라고 해"
      │
      ▼
 디자이너 메인 세션 ──보냄──▶ 팀 메인 세션 ◀──보냄── 개발자 메인 세션
                               │
                     ① 요청 줄 세우기(순서)
                     ② 충돌 확인(같은 곳을 고쳤나)
                     ③ 합치기 → 새 판 번호 부여
                     ④ 결과를 모두에게 알림
```

사람은 "보내 줘"만 말한다. 순서 정리와 합치기는 팀 메인 세션이 한다.

### 3-4. 연결 지도

- 프로젝트 → 사람 → 세션 → 산출물을 마인드맵처럼 보여 주는 기본 화면.
- 산출물을 누르면 바로 열린다. **판 번호**(1판 → 7판)로 변경 이력을 본다.
- 사람별 **업무량 막대**로 일이 한쪽에 몰리지 않았는지 확인한다.

### 3-5. 협업 대시보드

| 칸 | 보여 주는 것 |
|---|---|
| 목표 | 이번 프로젝트의 목표와 지침 |
| 계획 진척 | 계획서 항목별 완료·진행·미착수 |
| 세션 가동률 | 열려 있는 시간 중 실제로 일한 시간의 비율 |
| 오늘 후속 계획 | 오늘 남은 일과 담당 세션 |

대시보드는 팀원이 직접 꾸며 공유할 수 있다.

### 3-6. 메신저

- 왼쪽에 채널, 오른쪽에 대화(사내 협업 메신저와 같은 모양).
- 채널·개인 대화·멘션·답글·산출물 첨부·읽음 표시.
- **AI 본부장도 채널 구성원**이다. 본부장이 사람에게 직접 묻고 답을 받아 의도를 확인한다.

### 3-7. 지식위키

- 모든 세션의 대화 요약·결정 사항·용어·규칙·브랜드 속성을 본부장이 항목별로 정리한다.
- 새로 합류한 사람과 새로 연 세션이 위키를 먼저 읽고 일을 시작한다.
- 팀이 여러 개면 **공통분모 위키**(모든 팀이 지킬 것)와 **팀별 위키**를 나눠 관리한다.

### 3-8. AI 본부장

| 역할 | 하는 일 |
|---|---|
| 코칭 | 메인 세션이 놓친 요청이나 잘못 합친 것을 위키와 대조해 알려 줌 |
| 검수 | 계획서 항목과 실제 산출물을 대조, 다른 AI(지피티·재미나이 등)에게 교차 검수 맡김 |
| 멈춘 세션 깨우기 | 일정 시간 움직임이 없는 세션에 다음 할 일을 보냄(허락된 범위 안에서) |
| 당일 후속 계획 | 오늘 끊김 없이 이어질 일 목록을 세워 **노는 세션 0**을 목표로 함 |
| 의도 도출 | 메신저에서 사람에게 묻고 답을 받아 방향 확인 |
| 허브 | 복제본을 다른 팀에 보내 공통분모 위키를 관리, 좋은 발견을 전 팀에 전파 |

## 4. 작동 원리

### 4-1. 연결 구조 — 밖으로만 나가는 연결

```
   김디자이너 컴퓨터            중계 서버               이개발자 컴퓨터
  ┌────────────────┐       ┌──────────────┐       ┌────────────────┐
  │ 잇다 앱         │──────▶│              │◀──────│ 잇다 앱         │
  │  └ 클로드 세션들 │ 밖으로 │  프로젝트 방   │ 밖으로 │  └ 클로드 세션들 │
  └────────────────┘  연결  │  메시지 전달   │  연결  └────────────────┘
                           │  산출물 보관   │
                           └──────┬───────┘
                                  │
                         AI 본부장 · 지식위키
```

- 각 잇다 앱은 중계 서버에 **먼저 말을 거는 쪽**이다. 바깥에서 내 컴퓨터로 들어오는 문을 열지 않는다.
- 그래서 방화벽이나 공유기 설정을 바꿀 필요가 없다.
- 연결은 계속 열린 통로(웹소켓 방식)라서 메시지가 오면 바로 전달된다.

### 4-2. 한 번의 합치기 흐름

| 단계 | 누가 | 무엇을 |
|---|---|---|
| 1 | 디자이너 | 자기 메인 세션에 "팀 메인 세션에 보내 줘" |
| 2 | 디자이너 메인 세션 | 산출물과 설명을 묶어 중계 서버로 보냄 |
| 3 | 중계 서버 | 같은 프로젝트의 팀 메인 세션에 전달 |
| 4 | 팀 메인 세션 | 줄 세우기 → 충돌 확인 → 합치기 → 새 판 번호 |
| 5 | AI 본부장 | 위키·계획서와 대조해 검수, 빠진 것 알림 |
| 6 | 모두 | 연결 지도와 메신저에서 결과 확인 |

## 5. 보안 원칙

| 번호 | 원칙 | 내용 |
|---|---|---|
| 1 | 밖으로만 연결 | 내 컴퓨터에 들어오는 문을 열지 않는다 |
| 2 | 주인 허락 우선 | 남의 컴퓨터에서 명령을 실행하려면 그 컴퓨터 주인이 미리 허락해야 한다 |
| 3 | 본부장 권한 3단계 | 프로젝트 주인이 **읽기만 / 제안만 / 실행까지** 중 하나를 고른다 |
| 4 | 초대한 사람만 | 프로젝트에 초대된 사람과 세션만 같은 방에 들어온다 |
| 5 | 모든 일 기록 | 누가 무엇을 보냈고 무엇을 합쳤는지 기록을 남겨 되돌릴 수 있게 한다 |
| 6 | 민감 정보 가리기 | 비밀번호·열쇠 값 같은 정보는 보내기 전에 가리도록 경고한다 |
| 7 | 회사 밖 공유 통제 | 다른 회사(협력사)와의 연결은 관리자가 허락한 프로젝트로만 한정한다 |

> **현재 상태 알림**: 2026년 11월 시제품은 연결 동작을 확인하는 단계로, 위 원칙 중 **암호화·인증·조직 관리는 정식 제품에서 갖춘다**(「01-기획서」 9장). 시제품은 사내 시험용으로만 쓴다.

> 아래 금액과 구성은 **모두 예시**이며 원가·시장 조사를 거쳐 확정한다. AI 사용료(클로드 등)는 각 회사가 따로 낸다는 **가정**이다.

| AI 본부장 | 코칭만 | 코칭·검수·깨우기 | 전 기능 | 전 기능 + 복제·허브 |
| 공통분모 위키 | 없음 | 없음 | 회사 안 | 회사·협력사 사이 |

## 7. 도입 절차

```
 1주차              2주차               3~4주차             5주차 이후
┌──────────┐     ┌──────────┐      ┌──────────┐      ┌──────────┐
│ 준비      │ ──▶ │ 시범 팀    │ ──▶  │ 넓히기     │ ──▶  │ 허브 운영  │
│ 앱 설치   │     │ 프로젝트 1개│      │ 팀 2~3개   │      │ 본부장 복제 │
│ 계정 초대 │     │ 위키 첫 정리│      │ 공통 위키   │      │ 팀 간 전파  │
└──────────┘     └──────────┘      └──────────┘      └──────────┘
```

| 단계 | 할 일 | 담당 |
|---|---|---|
| 1. 준비 | 각자 컴퓨터에 잇다 설치, 회사 계정으로 로그인, 프로젝트 만들기 | 팀장 |
| 2. 규칙 정하기 | 본부장 권한(읽기만·제안만·실행까지), 도움 정도, 회사 밖 공유 여부 결정 | 팀장·관리자 |
| 3. 시범 프로젝트 | 작은 과제 하나로 "보내 줘 → 합치기" 흐름 익히기 | 시범 팀 |
| 4. 위키 다듬기 | 본부장이 만든 위키 초안을 사람이 확인·수정 | 팀 전원 |
| 5. 넓히기 | 다른 팀 추가, 공통분모 위키 시작 | 경영진 |
| 6. 돌아보기 | 세션 가동률·합치기 대기 시간 등 지표 확인 | 팀장 |

## 8. 자주 묻는 질문

**질문 1. 개발을 몰라도 쓸 수 있나요?**
네. 쉬운 채팅 방식으로 바꾸면 말풍선 대화로 보입니다. "이거 팀에 보내 줘"처럼 말로 요청하면 됩니다.

**질문 2. 동료 컴퓨터에 제 컴퓨터가 그대로 열리나요?**
아닙니다. 모든 컴퓨터는 중계 서버로만 연결합니다. 동료가 내 컴퓨터에서 무언가를 실행하려면 내가 미리 허락해야 합니다.

**질문 3. AI 본부장이 마음대로 일을 시키지 않나요?**
본부장 권한은 프로젝트 주인이 정합니다. "읽기만"으로 두면 지켜보고 알려 주기만 하고, "제안만"이면 제안 후 사람이 승인해야 실행됩니다.

**질문 4. 클로드 말고 다른 AI도 쓸 수 있나요?**
작업 세션은 클로드 코드를 기본으로 합니다. 검수 단계에서는 지피티·재미나이 같은 다른 AI에게 교차 검수를 맡기는 기능을 정식 제품에서 지원할 계획입니다.

**질문 5. 앱 개발팀만 쓰는 도구인가요?**
아닙니다. 화장품 제품 컨셉, 상세 페이지 문안, 협력사 이메일처럼 "산출물을 만들고 전달하는" 모든 업무에 씁니다.

**질문 6. 기존 사내 메신저와 무엇이 다른가요?**
기존 메신저는 **사람**을 잇습니다. 잇다는 사람이 쓰는 **AI 작업 창**을 잇고, 그 결과물을 자동으로 합치며, 본부장이 대화에 함께 참여합니다.

**질문 7. 같은 파일을 두 사람이 동시에 고치면 어떻게 되나요?**
팀 메인 세션이 요청을 줄 세우고 충돌을 확인합니다. 스스로 정리하기 어려운 충돌은 메신저로 두 사람에게 물어 결정을 받습니다.

**질문 8. 팀이 여러 개면 지식이 섞이지 않나요?**
팀별 위키는 따로 두고, 모든 팀이 지켜야 할 것만 **공통분모 위키**로 모읍니다. 어느 팀의 좋은 발견은 본부장이 골라 다른 팀에 전파합니다.
